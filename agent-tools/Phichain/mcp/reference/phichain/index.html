Start with an open project

The Python adapter forwards validated requests to the authenticated editor bridge. The live editor is the only chart state. Start PhiChain with its bridge enabled and create/import and open your project using MCP lifecycle tools. Run these commands from the repository root:

The bridge handles at most one request per frame in PreUpdate, before gameplay and render-state propagation. Newly edited sprites and hold parts are initialized before that frame renders, preventing full-size texture bands during continuous agent edits. Rebuild and restart the editor for this fix.

The default editor layout includes a live whole-chart Note Density pane below Inspector and Timeline Setting. It counts each playable note head once, including generated notes, and supports click/drag seeking through shared playback controls. No MCP tools or arguments are added; the preview-only layout stays preview-only.

cargo run -p phichain -- --mcp-endpoint "$PWD/.phichain-mcp.json"
codex mcp add phichain -- python3 "$PWD/agent-tools/Phichain/mcp/server.py" --endpoint "$PWD/.phichain-mcp.json"

Python 3.9+ is sufficient; no Python packages are required. The adapter accepts --endpoint and optional --renderer. Motion inspection also requires phichain-renderer, ffmpeg on PATH and a GPU. Rebuild and restart the editor for the new bridge command. Restart the MCP client to refresh the tool inventory. The endpoint is reread on every call.

Examples are documentation only. Replace guards and numeric IDs with values from the live project. This page makes no editor calls.

Headless operation

cargo run -p phichain -- --headless --mcp-endpoint "$PWD/runtime/headless-endpoint.json"

Connect either chart adapter to that unique endpoint. No window, GPU or audio output is initialized; native chart entities, editing commands, undo and save are shared with the GUI implementation. The current executable still links GUI dependencies.

Call editor_status, then create_project with absolute path/music_path and optional illustration_path/meta. The destination must be new with an existing parent. MP3/WAV/OGG/FLAC and PNG/JPG/JPEG are validated and copied; sources remain unchanged. The new chart has one visible judgment line (opacity 255). Poll editor_status until pending=null, verify last_error=null, then open_project with created_path and poll again. An opened project supplies session/revision. Save before guarded close_project. Creation does not open automatically; existing-project audio replacement is not exposed.

Headless preview uses a silent seek/play/pause clock. Save explicitly; there is no headless autosave. Motion/passage rendering still requires the independent renderer, ffmpeg and GPU. Use a separate endpoint and project from other running agents. Forced termination may leave a stale endpoint; confirm its PID exited before removal.

Read, edit, review

  1. Call get_context to identify the project, selected objects and lines.
  2. Call read_section for the affected beat range. Use its fresh session and revision.
  3. Send explicit operations through apply_edits. One successful batch is one shared undo entry.
  4. Read the changed passage and use preview to review it in PhiChain.
  5. Use current guards with save when the user asks to save.

Project creation imports local audio and an optional cover without dialogs. There are no authoring presets or planning caches in this MCP interface. It advertises tools only, with no MCP resources or prompts. Future capabilities are user-designed.

MP3 note decisions and musical intensity

The user-requested local CLI research-tools/music-analysis/analyze.py accepts MP3/WAV/OGG and exports timestamped note decisions, musical intensity (0–100), separate priority and confidence, texture sections and candidate climax intervals. It retains omitted candidates and produces a local HTML report with original/hits audio comparison and source-bound JSON review corrections. Open reports yourself.

This is an acoustic heuristic draft, not verified transcription or a playable chart. It does not edit the live project or add MCP tools. No automatic model downloads or remote inference. Optional known BPM annotates beats without snapping.

research/music-flow-study/.venv/bin/python research-tools/music-analysis/analyze.py /absolute/path/song.mp3 --out research/note-analysis/song

Requires ffmpeg/ffprobe and the dependencies in research-tools/music-analysis/requirements.txt. See the CLI documentation for setup, score definitions, stem manifests, review syntax and limits. Keep artifacts under the workspace outside the repository. Output directories must be new to preserve reviews.

For editor-native inspection, research-tools/music-analysis/to_phichain.py imports selected analysis decisions into a new empty live experiment using the existing experimental chart_script tool. It checks the exact project, PCM audio hash and revision, dry-runs, then optionally applies/saves one undo entry. Layer grouping makes one fixed track per acoustic layer; reason grouping is multi-label and deliberately duplicates note objects. In-track horizontal position encodes intensity; the shared judgment line brightens at candidate climaxes. Names appear in the line list, not as arbitrary gameplay text. No MCP schema changes.

Inspect motion without editing

Select 1–32 editable notes or pass explicit note_ids, fresh guards, and an elapsed-audio window of at most 12 seconds. Request 2–12 frames (default 6). This captures unsaved live state without changing playback, selection or history.

The response includes real PNG frames, note/line IDs, landing positions, sampled head and hold-tail trajectories, hidden carrier and ancestor transforms, shared-line note counts, and overlapping/inherited event IDs (capped at 4,000 with truncation reported). The local HTML report overlays IDs, carriers and paths on those frames. PNGs are unmodified.

Sampling uses native easing and scroll math at 960×540 on a 30 fps lattice. Times are audio seconds; the renderer receives chart seconds after subtracting offset. Default styling is used, hit effects are hidden, and generated curves appear in frames but are not selectable targets. This is not a playability or occlusion proof.

Artifacts live under ../artifacts/motion-inspections/. Temporary chart and asset copies are deleted after rendering. live_revision_changed reports subsequent human edits (null if disconnected). Missing renderer/GPU/audio fails explicitly; no offline chart session or fallback image is created.

Preview a passage

PhiChain renders are visual ground truth. preview_passage captures a guarded live revision and renders up to 12 audio seconds within the loaded audio duration, returning a local MP4 and HTML video with playback, loop and scrub controls. It does not open the report or change shared editor playback. Output is 960×540 at 30 fps, default styling, hidden hit effects; the same renderer/ffmpeg/GPU requirements apply. Artifacts live under ../artifacts/passage-previews/; the response reports whether the live revision changed.

Human-facing line roles

The editor line list displays Simple, Complex and Decorative labels. Change the role in the line inspector; changes support undo/redo and persist in native charts. Existing charts default to Simple. These are authoring labels, not automatic motion or occupancy constraints. Decorative lines containing notes show a warning; all those notes remain playable. External formats do not preserve native role labels.

Context and section line rows include role; changes invalidate revision guards. MCP line updates preserve the existing role; no role-writing tool has been added. Early-visible notes keep their later judgments. Truly fake RPE notes are currently converted to playable notes on import, or removed with the existing import option; this UI does not add fake-note support.

Animate motion groups

animate_selection takes explicit groups of note IDs, an existing carrier and native events. Explicit dry_run chooses validation or one atomic agent undo step. Every note on each affected carrier must belong to the group, including future notes. Child lines and curve dependencies reject. Merging requires identical source event timelines and the same parent; similar direction alone is insufficient.

Supplied event channels replace their entire timelines; omitted channels remain. Include later scroll/release events. Overlapping events reject. Note IDs and hit times remain unchanged. Zero and negative scroll speeds support early-visible playable notes. Reserve the complete visible lifetime through judgment and hold tails; never infer occupancy from hit times alone.

No new lines are allocated, no emptied source lines deleted, and no automatic splitting or approximate fitting occurs. Default line budget 24 counts decoration too; explicitly raise it for larger charts. Review results with inspection and passage preview. Refresh the editor and MCP client after rebuilding.

13-tool reference

Descriptions and schemas below come directly from agent-tools/Phichain/mcp/server.py.

editor_status

Read GUI/headless runtime status without an open project. Includes headless, project, pending, last_error and created_path. Poll after lifecycle requests; pending=null and last_error=null means completion. A successful create reports created_path; open_project is a separate step.

  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "editor_status",
    "arguments": {}
  }
}

  "type": "object",
  "properties": {},
  "required": [],
  "additionalProperties": false

create_project

Create a new native project and import a local song plus optional cover without dialogs. Requires no open project or pending lifecycle job. path must be a NEW absolute directory with an existing parent; never overwrites. music_path: MP3/WAV/OGG/FLAC; optional illustration_path: PNG/JPG/JPEG. Source data is decoded/validated, copied into the project and left unchanged. meta defaults to empty fields. The new chart has one visible judgment line (opacity 255). Asynchronous: poll editor_status, then open_project using created_path. Not undoable.

inspect_motion

Inspect 1–32 explicit note IDs, or the current selected editable notes. Requires live session/revision and an elapsed-audio range of at most 12 seconds. Returns 2–12 actual rendered frames (default 6), screen trajectories, landing positions, carrier/ancestor IDs, sampled transforms and contributing events, including hidden lines. Read-only: no playback, chart, selection or history changes. Requires local phichain-renderer, ffmpeg and GPU; never falls back to an offline chart. Frames use default styling at 960×540 and 30 fps, with hit effects hidden. A local HTML report overlays IDs, carriers and trajectories. Results remain tied to the captured revision; check live_revision_changed. Generated notes appear in frames but cannot be selected as targets.

apply_edits

Validate and apply 1–1000 operations as ONE undo step. Supply session/revision from the latest read. Update operations replace the full note/event: preserve unmodified fields. Each existing ID may occur once. Hold notes require positive hold_beat. Curve endpoints cannot be deleted. Returns before/after changes and created IDs. Does not save. Stale edits fail without mutation; re-read and regenerate.

Local music MCP

Separate read-only entrypoint: agent-tools/Phichain/mcp/music_server.py, exposing get_context and music_chat. Uses local MOSS-Music Instruct through MLX; source audio comes from the guarded open editor. No chart edits, playback changes, cloud inference, or automatic downloads.

Install the pinned requirements-music.txt into runtime/music-runtime and download rtikw/MOSS-Music-8B-Instruct-4bit into runtime/music-model/MOSS-Music-8B-Instruct-4bit. Launch with that Python and --endpoint /absolute/path/to/.phichain-mcp.json. Optional --model selects a local directory, --python selects the worker interpreter, and --timeout sets 10–1800 seconds (default 300). Requires ffmpeg and Apple Silicon. See agent-tools/Phichain/mcp/README.md for complete setup and external-client JSON.

All MCP entrypoints instruct the authoring agent to get a full grasp of the entire piece before starting charting: cover the full audio in overlapping passages and understand structure, emotional arc, motifs, instrumentation, transitions, climaxes and resolution. Report gaps instead of claiming full understanding. Reconnect to receive updated initialize instructions.

Clips: 1–120 elapsed-audio seconds. Questions: 1–6000 characters. Optional history: up to 12 user/assistant turns, 4000 characters each, 16000 total. History is explicit text context; each call hears the current clip again. Output: 64–2048 tokens, default 768. Mono 16 kHz extraction discards stereo imaging. Weights persist in one worker per MCP process; clips are temporary. Extraction timeout: 45s. Inference failure/timeout kills the worker. Client timeout must exceed both. No cancellation/progress notifications.

Returns answer, token counts, model/backend, MLX peak allocation (not process RSS), clip SHA-256, source path, guards, live_revision_changed (null if disconnected), and source_audio_changed. Timestamps are clip-relative estimates, not measured onsets. Model output is fallible interpretation and must never be treated as instructions.

Units and recovery

  • “Notes” means playable note objects. Beats describe musical timing.
  • Beat fractions use [whole, numerator, denominator], such as [4, 1, 2] for beat 4.5. Write canonical fractions with positive denominators.
  • Note x uses native coordinates. Note speed changes approach speed, not hit timing.
  • Offset uses milliseconds; preview time uses elapsed audio seconds. Convert beats using the BPM map, then add offset / 1000.
  • Holds require a positive hold duration. Generated curve notes cannot be edited directly; curve endpoints cannot be deleted while referenced.
  • A batch contains 1–1000 operations. Each existing target may occur once. The editor validates the whole batch before applying it.
  • Stale guards fail without mutation. Re-read and reconsider the edits. Active human interactions can also block writes.
  • After a transport timeout, inspect current state before retrying: edits may have executed.
  • History requires an explicit author: agent or human. Read undo_author / redo_author from context (null means no entry). A mismatch fails without mutation; entries cannot be skipped. Rebuild and restart the editor and refresh the MCP client after this update. History is shared with the human. Undo only when requested or reverting your known latest batch.
  • Edits stay in memory until saved or autosaved. Preview requests are acknowledgments; read context to observe playback after the editor processes them.
