Connect to the running editor

This is an implemented alternative MCP entrypoint on the experimental branch. It uses the same live PhiChain editor, endpoint and shared history as the minimal server. It does not run rpe-next or keep an offline chart store.

cargo build -p phichain
# Save your current work before restarting the editor with this build.
cargo run -p phichain -- --mcp-endpoint "$PWD/.phichain-mcp.json"
# Create/open a project through MCP, or add --headless above for no GUI:
codex mcp add phichain-agent -- python3 "$PWD/tools/phichain-mcp/agent_server.py" --endpoint "$PWD/.phichain-mcp.json"

Refresh the MCP client after registration. Prefer one PhiChain entry per chat to avoid duplicate tool names. Python 3.9+ is required. Transform/generate/script additionally require Node.js 22.13+ supporting permission mode on the MCP PATH; there are no npm dependencies. Rendering retains the native renderer/ffmpeg/GPU prerequisites. Old editor builds report unknown authoring bridge commands and must be rebuilt/restarted.

Examples are documentation only: replace IDs, guards and paths with current live values. Builds and tests verify mechanical correctness; model-generated chart quality is not established by this page.

For a windowless host, add --headless and use a separate endpoint. The headless lifecycle workflow documents create/import/open/status/close, silent timing, explicit save, and renderer requirements.

Read → compute → validate → commit → inspect

  1. editor_context identifies the current session, revision, lines and selected editable IDs.
  2. chart_read/chart_query reads exact native data and dependencies. chart_templates provides complete legal object shapes and easing forms.
  3. Choose chart_patch for individual fields, chart_transform for repeated numeric changes, chart_generate for template sequences, or chart_script for algorithms spanning several objects/collections.
  4. Set dry_run=true: the live editor validates the complete candidate without chart/history changes. Reinvoke deterministically with fresh guards and dry_run=false to commit one shared agent undo entry.
  5. Read changes, run diagnose and inspect actual renders via inspect_motion/preview_passage. Save through project_save only when requested.

Both dry and real writes validate session/revision and idle state on the editor thread. An intervening human edit invalidates the candidate. After timeouts reread current data/history before retrying. Successful earlier edits are not automatically rolled back. Existing history retains its explicit human/agent author match.

The native writable document

Seven fields: lines, notes, events, curve_tracks, meta, bpm_list and offset. Collections use ID keys. Existing IDs retain identity through moves and undo/redo. New objects use unique new:name aliases; a new carrier and its notes/events can be created in one candidate. created_ids returns the native IDs after commit. New lines receive missing native baseline channels (x/y/rotation=0, opacity=255, speed=10) so they actually render and scroll. Explicit channels are preserved, existing lines are untouched, and added baselines appear in dry-run diffs.

Unknown or missing native fields, arbitrary numeric IDs, cross-type IDs, missing references, cycles, duplicate root orders and invalid curve endpoints reject before mutation. Beat arrays must be canonical; BPM begins at beat zero. Native numeric fields round to f32. Candidate operations affect actual native entities, not an RPE export/import round trip.

Changing line_id preserves local note fields and judgment times. It does not preserve screen-space motion automatically when parent/event transforms differ. Motion review must include early appearances and hold tails. Generated curve notes are rebuilt derived state, never stable editable objects.

Computation and limits

The copied rpe-next numeric expression parser supports safe arithmetic, comparisons, functions and conditional expressions. Numeric object fields plus beat/i/N/u are available; time-field expression results convert to canonical beats at 1/10000 resolution. Script code instead uses synchronous JavaScript and the native constructors shown by chart_templates.

A fresh VM context in a separate memory-limited Node process receives only JSON data, script source and computational helpers. No process/require/editor/DOM/file/network API is supplied. Node permission mode restricts reads to adapter code and denies writes/process spawning; credentials and the endpoint are not passed. This is computation isolation, not a claim that Node VM is an OS security boundary. No async scripts. Default 10-second timeout; allowed 100–30,000 ms. Errors and timeout do not submit a candidate.

  • At most 20,000 editable objects; candidate bridge limit of 16 MiB may bind earlier (public MCP requests remain 1 MiB).
  • Patch: 1–2,000 operations. Generate: 1–10,000 objects. Read/query pages: at most 200.
  • Script input: 16 MiB; result: 8 MiB; final candidate bridge request must fit 16 MiB. Public MCP request: 1 MiB.
  • No-op candidates create no history entry. Dry runs are recomputed, not durable prepared-plan tokens.
  • Aliases: unique new:name, 5–80 ASCII bytes using letters, digits, underscore, hyphen or colon.

inspect_motion

Inspect 1–32 explicit note IDs, or the current selected editable notes. Requires live session/revision and an elapsed-audio range of at most 12 seconds. Returns 2–12 actual rendered frames (default 6), screen trajectories, landing positions, carrier/ancestor IDs, sampled transforms and contributing events, including hidden lines. Read-only: no playback, chart, selection or history changes. Requires local phichain-renderer, ffmpeg and GPU; never falls back to an offline chart. Frames use default styling at 960×540 and 30 fps, with hit effects hidden. A local HTML report overlays IDs, carriers and trajectories. Results remain tied to the captured revision; check live_revision_changed. Generated notes appear in frames but cannot be selected as targets.

What was ported

This branch ports the agent-to-chart writing vocabulary into PhiChain: field patches, batched expressions, templates and whole-candidate scripts. The expression parser and numbered easing functions were copied from rpe-next commit 274bc55866dc5893e68c95bb4107f79711f1aa1d; editor translation calls were replaced with standalone error messages. Those files retain PolyForm Noncommercial 1.0.0 and their required notices under tools/phichain-mcp/vendor/rpe-next/.

No foreign editor assets/runtime, noise areas, shader model, fake notes, text/noise fitting, aggregate trajectories, audio models, built-in model/chat loop, file workspace, VCS or collaboration were ported. Unsupported capabilities are not advertised as working tools. Native note/event algorithms can use chart_script, with PhiChain's existing rendering for review.
